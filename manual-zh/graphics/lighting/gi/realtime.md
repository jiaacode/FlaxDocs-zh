# 实时全局光照

![Flax 引擎中的实时 GI](/manual/media/realtime-gi.png)

在创建大型世界或光照条件不断变化的动态环境时（例如由于一天中的时间变化），你可以使用 **实时全局光照** 来渲染穿过场景的间接光线。

本文档页面解释了如何在项目中使用 GI。文末还包含一些有用的提示和技巧。

## 教程

要了解如何快速设置实时全局光照，请参阅[此教程](how-to-setup-gi.md)。

## 动态漫反射全局光照

![Flax 引擎中的 DDGI](/manual/media/ddgi.png)

[动态漫反射全局光照](https://morgan3d.github.io/articles/2019-04-01-ddgi/)（**DDGI**）是 Flax 中实现的一种算法，用于渲染带有间接光照的动态全局光照。

它使用光照探针（自动放置在世界空间中）在固定位置收集间接光照，然后在材质（不透明、透明和体积）中对其进行采样。为了防止光照泄漏（基于探针的解决方案常见问题），DDGI 算法会在每个探针周围渲染一个低分辨率深度缓冲区，并应用 *Chebyshev* 可见性权重。

DDGI 探针放置在摄像机周围，并分为一系列级联以覆盖整个场景。当摄像机在场景中移动时，探针会滚动以保持 GI 覆盖范围。

### DDGI 算法

Flax 对 DDGI 算法的实现使用了自定义的 **软件光线追踪** 解决方案和最多 **4 级联** 的自动 **滚动探针体积**。观看以下视频，了解有关此渲染功能的技术和艺术方面的更多信息：

* "Scaling Probe-Based Real-Time Dynamic Global Illumination for Production", [https://jcgt.org/published/0010/02/01/](https://jcgt.org/published/0010/02/01/)

### 使用 DDGI

![在图形设置中启用 DDGI](/manual/media/ddgi-enabled-settings.png)

在 [图形设置](../../../editor/game-settings/graphics-settings.md) 或 [后期处理效果体积](../../post-effects/post-fx-volumes.md) 的后期处理 *全局光照* 设置中，将 **模式** 设置为 **DDGI**。

然后你可以调整以下选项：

| 选项           | 描述                                                         |
| -------------- | ------------------------------------------------------------ |
| **强度**       | 全局光照间接光照强度缩放。可用于增强或减弱 GI 效果。         |
| **反弹强度**   | 全局光照无限间接光照反弹强度缩放。可用于增强或减弱表面光线反弹的 GI 效果。 |
| **时间响应**   | 定义 GI 在当前帧和历史缓冲区之间混合的速度。较低的值更新 GI 更快，但抖动和噪点更多。如果你的游戏中的摄像机移动不多，建议使用接近 1 的值。 |
| **距离**       | 全局光照效果的绘制距离。超出范围之外的场景将使用回退辐照度。 |
| **回退辐照度** | GI 范围外用作回退的辐照度光照，以防止 GI 范围之外的场景完全变黑。 |

[图形设置](../../../editor/game-settings/graphics-settings.md) 中的其他相关选项：

| 选项                   | 描述                                                         |
| ---------------------- | ------------------------------------------------------------ |
| **GI 质量**            | 全局光照质量。控制 GI 效果的质量。                           |
| **GI 探针间距**        | 全局光照探针间距距离（以世界单位为单位）。定义 GI 分辨率的质量。调整为 200-500 以改善性能并降低低频 GI 数据。 |
| **全局表面图集分辨率** | 全局表面图集分辨率。如果图集因溢出而“闪烁”，请调整它（例如调整为 4096）。 |

你可以在图形设置中使用 *全局表面图集分辨率* 属性调整最大图集分辨率。需要高视距的大型场景应使用更大的图集尺寸，以尽可能用 GI 覆盖更多的对象。

### 光线追踪反射

![DDGI 光线追踪反射](/manual/media/ddgi-reflections.png)

除了漫反射光照之外，还可以通过在 *屏幕空间反射* 类别（在图形设置或后期处理效果体积中）将 **追踪模式** 更改为 **软件追踪**，使用全局光照来改善镜面反射光照。

这使用了我们对全局表面图集的自定义软件追踪，作为默认 *屏幕追踪*（也称为 *屏幕空间反射*）的回退方法，后者执行屏幕空间、深度缓冲区追踪和场景颜色采样。

然而，这种屏幕空间渲染方法有一个主要限制，即只有屏幕上可见的像素才能用于反射。使用利用全局 SDF 和全局表面图集的软件光线追踪，将使用全场景光线追踪，即使对于屏幕外的对象也能提供反射。

使用此功能可能会对性能产生显著影响（GPU 时间约 0.5-1ms），但通过使光照更加真实和完整，可以极大地增强场景的外观。

### 软件光线追踪

原始 DDGI 算法与 Flax 实现之间的关键区别在于使用了自定义的 **软件光线追踪而非硬件光线追踪**。这是因为我们希望即使在通常不支持 RTX 功能的较旧硬件上也能支持使用实时 GI。

我们的实现使用光栅化为[全局 SDF](../../models/sdf.md) 的 *有符号距离场* 来在场景中执行光线追踪。然而，这仅返回光线与场景几何体之间的交点，而 GI 还需要评估直接和反弹的间接光照。

为了解决这个问题，我们实现了 **全局表面图集**，这是一种渲染通道，将摄像机附近的场景对象表面渲染到一个巨大的图集纹理中，并带有对象侧面的投影。这类似于 GBuffer 渲染，材质输出低分辨率颜色、自发光、粗糙度、法线、深度等。然后我们对这些像素进行光照，以根据表面的材质评估直接和间接光照。全局表面图集允许在世界中的任意位置采样这些表面，这使得在全局 SDF 追踪命中位置评估光照成为可能。

### 调试可视化

![全局表面图集调试预览](/manual/media/ddgi-global-surface-atlas.png)

上图显示了全局表面图集的调试可视化（在任何 3D 视口中通过 **视图 -> 调试视图 -> 全局表面图集** 访问）。

视图的主要部分包含光栅化的全局 SDF 以及采样的图集光照。**这就是软件光线追踪器所看到的**，并用于评估全局光照，因此 **在关卡中处理 GI 时，必须使用此视口来检查场景**。

在右侧，从顶部开始，你可以看到图集表面的漫反射颜色、法线向量和打包的其他属性（AO、粗糙度、金属度）。

如你所见，全局表面图集是场景的低分辨率表示，结合全局 SDF，在摄像机附近具有 **10-20cm 的精度**。它可以有效地 **覆盖最远 500m 的场景**，即使在远离摄像机的地方也能获得全局光照。

### 调试表面图集

![调试全局表面图集](/manual/media/ddgi-surface-atlas-debug.png)

在 Flax 中使用 DDGI 时，一个常见问题是全局表面图集中对象表面的表示效率低下。在许多情况下，这是由不准确的 SDF 网格表示引起的，在较少见的情况下，图集中对象的表示是缺失的。

表面图集的调试视口会在漫反射视口（右上角那个）中以 **粉红色高亮显示缺失的表面像素**。这通常是具有内部空间的大型网格，因为对象投影是从 6 个侧面（顶部、底部、左、右、前和后）执行的，因此会遗漏内部侧面。

可能会出现一些最小的粉红色斑点，这是正常的，不是大问题，但为了获得良好的间接光照质量，仍应尽量减少。有几种方法可以在场景中改善这一点：

* 尝试将大型对象拆分为更小的部分（例如，房屋建筑墙壁拆分为 4 个部分，带有单独的屋顶和地板），
* 为网格设置 LOD（表面图集始终使用最低 LOD 进行光栅化）。

### 调试 DDGI 探针

![调试 DDGI 探针](/manual/media/ddgi-probes.png)

使用 **视图 -> 调试视图 -> 全局光照** 在视口中预览 DDGI 探针。这对于查看自动探针重定位是否导致问题非常有用。

### DDGI 提示与技巧

* 为场景设置正确的[全局 SDF](../../models/sdf.md)。
* 在静态场景对象上使用 `StaticFlags` 以优化渲染。
* 如果对象表面频繁改变颜色/自发光（例如在着色器中动画或在运行时切换），请从中移除 `StaticFlags.Lightmap`。这将导致其频繁更新而不是被缓存。
* 为复杂网格使用 LOD（全局表面图集光栅化对于三角形数量较低的网格更快）。
* 材质中的 **位置偏移不受支持**，可能会导致光照问题。
* **网格需要有简单的内部空间**（例如具有独立墙壁的房屋模型）——使用全局表面图集调试视图来分析你的内容。
* 像电视屏幕这样的大型自发光表面可能需要额外的光源来正确覆盖镜面光照。
* 较小的自发光对象可能会因渲染资源分辨率降低导致的缺陷而闪烁。

### DDGI 成本

DDGI 的总 GPU 内存使用量在 200-400 MB 之间（取决于质量和内容）：
* DDGI 使用高达 69 MB 的 GPU 内存（取决于质量）*(nice)*
* 全局表面图集使用约 49 MB 的 GPU 内存（使用更高分辨率时可能更多）
* 全局 SDF 使用高达 130 MB 的 GPU 内存（取决于质量）
* 模型 SDF 可能使用几 MB 的 GPU 内存

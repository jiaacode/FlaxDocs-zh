# Flax 1.10 发布说明

## 亮点

### 新的泛光

![新的泛光渲染](/manual/media/bloom.png)

**泛光效果** 采用了新的更平滑的渲染方式，提供了 **更逼真的效果**。它采用了基于 mipmap 的双重过滤，并带有可配置的软拐点。新的视觉效果更柔和、更稳定，并且具有更广泛的扩散效果，在观察亮点时会自然扩散。

### 多重混合编辑器改进

![新的多重混合 2D 编辑器](/manual/media/multi-blend-editor.gif)

新的多重混合 2D 编辑器将可视化三角化的混合空间，并带有渐变和高亮显示，以便更好地理解动画是如何被插值的。这准确地表示了底层运行动画混合的逻辑。

### 新的网格顶点格式

![新的网格顶点格式](/manual/media/vertex-layout.png)

此版本中最大的变化之一是 **对网格使用的顶点缓冲区进行了完全重构**。静态网格和蒙皮网格将不再使用固定的顶点格式。相反，它们将允许更灵活和完全可自定义的数据。这是通过添加新的 `GPUVertexLayout` 并在顶点着色器中移除固定格式依赖来实现的（请参阅 *迁移指南*）。

![多个纹理坐标网格](/manual/media/texcoords.png)

此更改带来了多个好处：
* 更优化的模型资源数据（在导入时剥离未使用的属性），
* 顶点数据量化（每个网格可以为顶点位置或 UV 值使用不同的精度），
* 支持多达 `4` 个纹理通道，
* 支持蒙皮模型中多达 `65535` 个骨骼，
* 支持蒙皮模型的顶点颜色，
* 支持游戏使用的非标准网格数据格式。

![多个纹理坐标通道](/manual/media/multiple-uvs.png)

### 新的动画重定向

![新的动画重定向](/manual/media/animation-retargeting.gif)

我们对 **动画重定向** 进行了重大改进。在上面的 GIF 中，来自 Synty 的各种角色使用不同的骨骼（来自不同的资源包），并正确播放相同的动画。要了解有关此功能的更多信息，请参阅[动画重定向文档](../../animation/animation/retargeting.md)。

### 网络优化

我们看到越来越多使用内置网络的 Flax 游戏。这促使我们对网络系统进行了重大的性能优化，例如：
* RPC 和复制使用的对象 ID 和类型名称现在使用优化的 32 位键，
* 四元数使用量化，将平均传输率降低了 56%（例如，`Identity` 值仅为 1 个字节，而不是 16 个字节），
* 复制系统将在发送复制消息之前检查对象数据是否已更改。

这些改进大大减少了网络传输。例如，在 [Arizona Framework 示例](https://github.com/FlaxEngine/ArizonaFrameworkSample) 中，使用 1 个主机和 1 个客户端，服务器的网络发送速率从 36kB/s 下降到 5kB/s。

### 调试命令

![输出日志中的调试命令](/manual/media/debug-commands-output-log.gif)

新的 **调试命令** 系统随 Flax 1.10 一起推出，并在输出日志窗口内提供了新的控制台。`DebugCommand` 是一个可以放置在类、字段、方法和属性上的特性，用于将它们暴露出来以供配置、模组或工具使用。

[输出日志](../../editor/windows/output-log.md) 是显示完整日志的编辑器窗口。现在，在该窗口的底部，有一个输入命令字段，可用于运行命令。你可以输入命令，并会自动弹出搜索框，根据输入的值显示类似的命令。使用方向键在弹出列表中导航。Tab 键可用于根据最佳匹配自动补全命令。最后，当输入为空时，你可以使用向上方向键在命令历史记录中导航并重新尝试其中的一个。

对于游戏内控制台，我们通过 [Arizona 框架](https://github.com/FlaxEngine/ArizonaFramework) 中的 ImGui 系统添加了一个。

![游戏内调试命令](/manual/media/debug-commands-in-game.png)

完整的文档可在[此处](../../scripting/advanced/debug-commands.md)获得。

### 按钮特性

![按钮特性](/manual/media/button-attribute.png)

我们做到了！最后，`Button` 特性出现在 C# 和 C++ 脚本中，用于快速注释函数，以便在编辑器属性窗口中向用户公开，供用户点击。这在原型设计程序化关卡生成系统或其他随机化/基于代码的算法时非常方便。它适用于编辑时或运行模式下的静态方法和成员方法。

### 曲线编辑改进

![曲线编辑改进](/manual/media/curve-editing.gif)

此更新为 **曲线编辑器** 带来了各种修复和改进。最终，稳定了缩放和平移，实现了更稳健的编辑。

## 迁移指南

### GPU 顶点布局

顶点着色器不再需要使用 `META_VS_IN_ELEMENT`。现在，在从代码创建缓冲区时，通过 `GPUBufferDescription` 将 `GPUVertexLayout` 传递给顶点缓冲区。你可以通过 `GPUVertexLayout::Get` 获取顶点缓冲区布局，以从代码中定义与传递给这些缓冲区的数据匹配的顶点结构布局。着色器不再需要依赖于特定的数据格式，这提供了更大的灵活性。

在代码中定义顶点结构并使用缓冲区创建的示例，该缓冲区与顶点元素的数据类型匹配（C++ 和 C# 都存在相同的 API）：

```cpp
struct Vertex
{
    Float3 Position;
    Color32 Color;
};

auto layout = GPUVertexLayout::Get({
    // type, slot, offset, instanced, format
    { VertexElement::Types::Position, 0, 0, 0, PixelFormat::R32G32B32_Float },
    { VertexElement::Types::Color, 0, 12, 0, PixelFormat::R8G8B8A8_UNorm },
});
```

***

### 网格数据

`Model` 和 `AnimatedModel` 资源支持可变顶点格式，使用新的数据流而不是固定的顶点结构。这为网格导入提供了更大的灵活性，以实现更优化的数据布局和量化。为了提供对网格数据的简单读写访问，添加了新的 `MeshAccessor` API（C++ 和 C#）：

```cs
var assessor = new MeshAccessor();
if (assessor.LoadMesh(mesh)) // 获取网格数据
    return;
var positionStream = assessor.Position(); // 访问顶点位置数据流
if (!positionStream.IsValid)
    return;
var count = positionStream.Count;
for (int i = 0; i < count; i++)
{
    var position = positionStream.GetFloat3(i);
    // 修改数据...
    positionStream.SetFloat3(i, position);
}
assessor.UpdateMesh(mesh); // 写回网格
```

***

`MeshAccessor` 支持所有顶点元素格式，并且可以执行自动转换以方便使用。例如，网格数据可以存储为 `R10G10B10A2_UNorm`，但代码可以将其作为 `Float4` 访问。

### 其他更改

* C++ `Nullable<T>` 已被重构以更加一致。更新使用它的代码。
* C++ `Vector3::Angle` 现在返回以度为单位的值，而不是弧度，就像 C# API 一样。
* 9-Slicing 纹理/精灵画笔已被修复，以正确计算边框大小，这将破坏资源中的现有使用。
* 当加载使用已弃用数据格式的资源（例如场景或预制体）时，编辑器将自动保存它以将数据升级到最新格式。资源和对象反序列化器可以使用 `ContentDeprecated::Mark()` 来指示这种需求。

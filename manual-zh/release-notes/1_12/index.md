# Flax 1.12 发布说明

## 亮点

### Web 支持

![Flax 引擎中的 Web 支持](/manual/media/web.png)

我们做到了！Flax 1.12 带来了对 **构建 Web 游戏** 的初始支持，这些游戏可以在浏览器中运行。我们使用最新的 **WebGPU** 来绘制高质量和高性能的图形。引擎已经过优化，可以在浏览器环境中高效运行，同时支持大多数功能。现在，你可以导出你的游戏并将其托管在线上（例如在 [itch.io](https://itch.io/) 上），这降低了 Flax 的采用门槛，尤其是对于独立开发者和爱好者。

为了庆祝这一突破性进展，我们将 [Kenney](https://kenney.nl/) 制作的一个简单赛车游戏移植到了 Flax。该项目已在[此处开源](https://github.com/FlaxEngine/FlaxWebRacing)。你可以在此处游玩它：

请参阅专门的文档以了解有关 [Web 开发](../../platforms/web.md) 的更多信息。

### 弹簧骨骼物理

| 关闭                                                         | 开启                                                         |
| ------------------------------------------------------------ | ------------------------------------------------------------ |
| ![无弹簧骨骼物理](../../animation/anim-graph/media/spring-bone-off.gif) | ![有弹簧骨骼物理](../../animation/anim-graph/media/spring-bone-on.gif) |

新的 **弹簧骨骼物理** 节点为一连串的骨骼节点模拟柔软的、基于物理的拖尾运动——例如触角、尾巴或布条。根骨骼保持固定在你的常规动画上，而每个后续骨骼都会跟随动态的二次运动（摇摆、飘动、抖动），自然地反应重力、风和运动。你可以控制骨骼的硬度、重量或灵活性，限制它们可以移动的幅度，并与任何标准动画系统结合（这保留了你角色的主要动画，只影响模拟的骨骼）。

![Flax 引擎中的弹簧骨骼物理节点](../../animation/anim-graph/media/spring-bone-node.png)

### 图编辑器新外观

![图编辑器新外观](/manual/media/new-visject.png)

*Visject*，我们图编辑器的代号，已经用新的彩色风格进行了更新。它大大 **提高了图的可读性**。材质、粒子发射器、行为树、可视化脚本和动画图的编辑变得更加流畅和愉快。

有许多更改和迭代，太多了无法一一列举。仅举几例：
* 节点现在将根据其内容自动调整大小，
* 节点现在带有轻微的阴影，并且背景中增加了微弱的网格，
* 选择轮廓的厚度已增加，
* 节点布局周围的边距和内边距已重构，
* 各种节点获得了替代标题，以改善对它们的搜索，
* 曲线节点可以调整大小，
* 选中的节点可以通过按 `Shift + F` 聚焦，
* 节点标题现在有颜色，可以快速识别节点的类型。

### MSDF 字体

![MSDF 字体](/manual/media/font-bitma-vs-msdf.png)

**多通道有符号距离场**（`MSDF`）字体即将登陆 Flax！这种字体光栅化算法计算到字形边缘的距离，从而在大尺寸下提供高质量的字体。MSDF 的额外好处是能够制作有趣的文本效果，例如轮廓、发光、阴影、程序化纹理等。

### DDGI 已可用于生产

![DDGI 已可用于生产](/manual/media/ddgi.png)

在过去几个月中，我们对 [动态漫反射全局光照](../../graphics/lighting/gi/realtime.md)（DDGI）的实现进行了各种改进，从而实现了更快、**改进的光线追踪实时 GI**（基于软件追踪 SDF）。长期存在的颜色偏向黄色的问题已被修复，间接阴影区域现在具有更高的对比度。探针采样算法已重构，以支持在附近没有 GI 信息的区域绘制像素时使用回退探针。这修复了大型房间或开放世界地图中烟雾粒子或角色上的光照问题，这些地方 GI 探针被放置在远离光照对象的位置。

在渲染方面，屏幕空间反射追踪已重构为使用 Hi-Z 缓冲区和更优化的合成通道，这大大提高了其性能。此外，我们通过执行更好的时间采样和过滤，在保持质量的同时降低了体积雾的分辨率。现在，[图形功能巡览项目](../../samples-tutorials/samples/index.md) **在 RTX 2080 Ti 上以原生 4K 分辨率（3840x2160）运行约 150fps，无需任何升采样**。更复杂的场景也应该受益，例如 [Flax Tech Demo 2022](https://store.steampowered.com/app/2138130/Flax_Engine__Tech_Demo_2022/) 获得了约 10% 的提升。

### 方向 Gizmo

![方向 Gizmo](/manual/media/direction-gizmo.gif)

是否曾在 3D 空间中迷失方向？不用担心，**新的方向 Gizmo** 会为你指明方向（右上角）。你可以使用它来查看编辑器摄像机的朝向，或单击其中一个轴圆圈使摄像机从该方向查看。它可以在编辑器选项中切换或调整。

### *Good Game* 视图

按 *G* 键，编辑器将从主编辑器窗口中隐藏所有小部件以及调试绘制。不用担心，你可以再次按 *G* 键恢复所有内容。你也可以**按 *P* 键切换导航网格调试绘制的可见性**。

### SDL 平台后端

Flax 在平台 API（例如窗口、输入、文件系统、日志等）上实现了自己的抽象层。这允许在控制台、移动设备和桌面等不同平台上运行相同的庞大引擎代码库。在 Linux 上，我们依赖自己的 `X11` 实现来处理窗口和输入，这对高级用户来说不够稳定。这就是为什么我们添加了使用 `SDL3` 库编译引擎的选项来处理输入和窗口管理。Flax 现在默认在 Linux 上使用 SDL，也可以选择在 macOS 和 Windows 上编译。

现在，**Linux 开发者可以使用 Wayland 或 X11**，并在 Linux 上使用编辑器开发游戏时获得更稳定的用户体验。

### 内容窗口中的树视图

![内容窗口中的树视图](/manual/media/content-tree-view.png)

内容窗口现在具有更**紧凑的树视图**。它在一个可展开和折叠的树中显示文件夹和项目。这意味着你现在可以将内容面板停靠在其他窗口旁边，同时保留完整功能。

### 环境探针的盒体投影

![环境探针的盒体投影](/manual/media/env-probes-box.png)

环境探针获得了新的 *盒体投影* 选项，以更优的方式为室内设置反射。它使反射视差正确，就好像它们是由定向盒体体积投射的，而不是球形形状。

### Visject Wrangler

![Visject Wrangler](/manual/media/visject-wrangler.gif)

连接节点是你在图编辑器中经常做的事情。Flax 1.12 引入了一个 **延迟连接功能**。要使用它，只需将鼠标光标悬停在节点附近，按住 *Alt* 键并按住 *鼠标右键*，然后拖向另一个节点。Flax 将自动在两个节点之间建立最佳连接。你现在还可以**将节点插入现有连接**。为此，将一个节点拖到两个节点之间的连接上。如果需要，Flax 将自动连接该节点并**移动其他节点以腾出空间**。现在还可以通过按住 *Alt* 键移动节点，从现有连接中**移除一个节点，同时保持该连接中的其他节点**。

### 线性色彩空间工作流

Flax 光照和纹理管线有一个错误，导入的颜色贴图不能正确匹配 sRGB 曲线。引擎后期处理和色调映射被调整以使其看起来大致正确，但颜色并不像它们应该的那样精确。Flax 1.12 在[图形设置](../../editor/game-settings/graphics-settings.md)中附带了一个新选项 `Gamma Color Space`，默认情况下勾选，保留旧的行为。然而，我们建议新项目禁用它并**使用线性色彩空间工作流**，它以正确的 sRGB 处理方式导入纹理。请参阅下面的 `迁移指南` 部分以了解更多信息。在不久的将来，我们计划默认将所有新项目迁移到新行为。

### 新的调试工具

![新的 GPU 性能分析器转储命令](/manual/media/gpu-profiler-dump.png)

使用新的 `ProfilerGPU.Dump` 命令快速分析渲染性能。它适用于编辑器和游戏构建（`Development`/`Debug`），并输出帧统计信息的摘要，按绘制事件层级分解，每个事件都包含以毫秒为单位的持续时间和占帧时间的百分比。默认情况下，它测量 `4` 帧的性能并平均结果，以实现更准确的 A/B 测试。

此外，`GPUDevice.DumpResources` 命令记录所有 GPU 资源，并附带详细的内存和使用统计信息，用于高级调试。

## 迁移指南

### sRGB 纹理和线性色彩空间

[图形设置](../../editor/game-settings/graphics-settings.md) 有一个新选项 `Gamma Color Space`，用于控制导入 sRGB 颜色纹理的逻辑。它默认勾选，保留引擎的现有行为，这意味着项目将保持不变，并将继续使用相同的纹理选项和颜色处理。当未勾选时，作为 sRGB 导入的颜色纹理将被正确照亮，以输出与输入纹理完全相同的颜色。此选项影响最终图像到窗口后缓冲区的呈现，意味着所有光照操作都在线性色彩空间中正确执行。

此选项可用于现有项目。要执行迁移，我们建议：
* 取消勾选 `Gamma Color Space`，
* 重新导入所有 `sRGB` 纹理，
* 调整后期处理设置：
  * 全局饱和度调整为 `1.1`，
  * 全局伽马调整为 `0.9`，
  * 预曝光调整为 `-0.5`，
* 在材质中使用 `Linear to sRGB` 和 `sRGB to Linear` 节点，
* 遵循[新文档](../../graphics/lighting/color-space.md)。

### API 更改

* 使用 `InverseSquaredFalloff` 的点光源和聚光灯现已修复，不需要高 `Brightness` 值（旧值会自动转换）。
* `CreateWindowSettings::IsRegularWindow` 已弃用，取而代之的是新的 `WindowType` 枚举。
* Visject Surface API 发生了很大变化，请参阅仓库以获取详细的更新日志。

### 已知问题

* 在 Linux 上使用 `X11` 时，如果 `XInput2` 处于活动状态，新的 `SDL` 平台后端无法与拖放一起工作。使用 Wayland（`-wayland` 命令参数）或在 X11 上的 Linux 使用 `SDL: false` 编译引擎。

### 平台更新

我们更新了各种平台的最低版本，以支持最新的功能和稳定性：
* macOS - XCode 版本 `16.4`（或更新版本），
* Android - NDK 版本 `27`（或更新版本）。

# Flax 发布策略

本文档涵盖了 Flax 引擎的发布计划，并描述了版本号命名方法。

## 版本号

Flax 使用基于 `major.minor[.build[.revision]]` 公式的版本号，其中：

- **Major**：主版本号，当新的产品版本发布且包含大量更改（包括重大 API 重构和设计概念修改）时更改。
- **Minor**：次版本号，在引擎更新带来质量改进和新功能时更改。次版本之间的升级通常较为容易，因为只有个别 API 可能有所不同。
- **Build**：构建号，每次引擎发布时递增，也用于维护性修复更新。它不影响 API。
- **Revision**：版本修订号。用于区分同一引擎发布的不同修订版（如补丁）。例如，`1.7.6403.1` 在 UI 中显示为 `1.7.1` 以提高可读性（`1.7` 发布的第 1 个补丁）。

相同的版本号方案用于二进制文件（原生和托管 C#）以及游戏或项目文件。

## 分支

`major.minor` 的组合称为 `稳定分支`，用于维护和支持的分离（请参见[分支](https://github.com/FlaxEngine/FlaxEngine/branches)）。通过这种方式，我们可以为多个发布版本（最新版本以及过去需要的版本）分别应用热修复和安全更新。

大多数活跃的开发工作都在 `master` 分支上进行，该分支用于下一次引擎更新。更改也可以从 `master` 向后移植到特定的发布分支。在稳定发布后不久，我们会将 `master` 保留用于热修复和进一步稳定（例如 1-2 周），然后再合并任何新功能或破坏性更改。

## 支持

稳定更新（例如 `1.7`、`1.8`）的目标是大约每 4 个月发布一次。然后，我们通过补丁更新（例如 `1.7.2`、`1.7.3`）来支持最新的发布版本。

任何已弃用的功能或 API 在移除前至少维护一年。对内容数据或项目格式的更改至少维护两年（出于向后兼容性的原因）。
